# التشفير وضمان "صفر إنترنت" — ما تغيّر في هذه الجولة

## 1. التشفير الفعلي (قبل/بعد)

**قبل:** `zustand persist` كان يكتب كل شيء (الرموز، الخزنة، الإعدادات) كـ JSON نص صريح مباشرة في `localStorage` تحت مفتاح `duress-security-app`.

**بعد:**
- أضيف `src/lib/secure-storage.ts`: طبقة تخزين جديدة تحل محل `localStorage` الافتراضي في `zustand persist` (عبر `storage: createJSONStorage(() => secureStorage)` في `src/lib/store.ts`).
- **على بناء Android الفعلي (Capacitor):** كل قراءة/كتابة تمر عبر Plugin أصلي جديد `SecureVault`
  (`android-native/plugin/.../vault/SecureVaultPlugin.kt`) يستخدم
  `androidx.security.crypto.EncryptedSharedPreferences`، ومفتاح التشفير نفسه محفوظ داخل **Android Keystore** (AES-256-GCM، ومدعوم بالعتاد/StrongBox إذا الجهاز يدعمه) ولا يغادر الـ Keystore أبداً ولا يصل لا لـ JavaScript ولا للقرص بشكل صريح.
- **على معاينة المتصفح/`npm run dev`** (لا يوجد Keystore داخل صفحة ويب): يتم اللجوء لتشفير AES-GCM بمفتاح يُولَّد ويُحفظ في IndexedDB. هذا أفضل من النص الصريح، لكنه **ليس بديلاً حقيقياً عن Keystore** — أي سكربت يشتغل على نفس الأصل (origin) يقدر يقرأ المفتاح من IndexedDB. الملف نفسه موثّق بهذا الفرق بصراحة ولا يدّعي عكس ذلك.
- رمز `7777` (المسح الطارئ) الآن يمسح أيضاً القيمة المشفّرة عبر `clearSecureStore()` بالإضافة لتنظيف `localStorage`/`sessionStorage`/`IndexedDB`/`Cache Storage` القديم (`wipe-screen.tsx`).

## 2. ضمان "التطبيق ما يتصل بالإنترنت نهائياً"

في هذا المشروع يوجد **طبقتان** تضمنان هذا الأمر، إحداهما أقوى من الثانية:

1. **الضمان الحقيقي (على مستوى نظام أندرويد):** `android-native/manifest-additions.xml` **لا يطلب صلاحية `android.permission.INTERNET` إطلاقاً** — لا قبل هذه الجولة ولا بعدها. بدون هذه الصلاحية، أندرويد يمنع أي socket شبكة للتطبيق على مستوى النواة (kernel)، بغض النظر عما يحاول أي كود (JS أو Kotlin) فعله. هذا غير قابل للتجاوز من داخل التطبيق نفسه، وهو أقوى ضمان ممكن تقنياً.
2. **طبقة إضافية على مستوى الواجهة (JavaScript):** `src/lib/network-guard.ts` أصبح يمنع أي طلب `fetch`/`XMLHttpRequest` لغير نفس الأصل (same-origin) — حتى لو حاول كود مستقبلي يستورد شيء بالخطأ. النسخة القديمة كانت تستثني نطاق `grok.com` (لغرض معاينة منصة البناء)؛ تم حذف هذا الاستثناء بالكامل لأن هذا تطبيق مستقل ولا داعي أبداً لأي اتصال خارجي.
3. أزيل من نقطة الدخول (`src/routes/__root.tsx`) تضمين `AuthProvider` و`PreviewHostBridge` — وهما بقايا قالب منصة بناء الموقع (تسجيل دخول/معاينة iframe) لا علاقة لهما بوظيفة تطبيق الحماية، وكانا قد يحاولان عمل طلب شبكة عند الإقلاع حتى لو كان سيُرفض. ملفاتهما الأصلية (`src/lib/auth/*`, `src/lib/app-data/*`, `src/components/preview-host-bridge.tsx`) تُركت كما هي بدون حذف (لتفادي كسر أي شيء لم أتمكن من اختباره فعلياً)، لكنها غير مستوردة في أي مسار يصل لتطبيق الحماية نفسه، وأيضاً بناء الموبايل (`npm run build:mobile`) أصلاً لا يضم أي خادم (`vite.config.ts` لا يُفعّل Nitro عند `MOBILE_BUILD=1`).

## 3. ما لم يتغيّر (لأنه كان صحيحاً أصلاً)
- لا يوجد ولا كان موجوداً أي استدعاء `DevicePolicyManager.wipeData()`.
- لا يوجد طلب صلاحية إنترنت بأي صيغة.
- منطق الرموز الأربعة (`0000`/`7777`/`5555`/رمز مرفوض) لم يتغيّر، فقط طبقة التخزين تحته.

## 4. ما لم يتم التحقق منه فعلياً في هذه الجلسة (كن صريحاً مع نفسك قبل الاعتماد عليه)
- **لم يُشغَّل `npm install`** (لا يوجد اتصال إنترنت في بيئة التنفيذ هنا)، وبالتالي:
  - لم يُشغَّل `npm run typecheck` بمشروع كامل الاعتماديات (تم فقط فحص جزئي لصحة الصياغة بـ TypeScript compiler منفصل على الملفات المعدّلة تحديداً — مرّت بدون أخطاء بنيوية، فقط تحذيرات متوقعة بسبب غياب حزم `@types`).
  - لم يُشغَّل `npm test` الكامل، ولا `gradle assembleDebug`.
- **لم يُبنَ APK** في هذه البيئة لعدم توفر Android SDK/Gradle هنا.
- Kotlin الجديد (`SecureVaultPlugin.kt`) روجع يدوياً (توازن الأقواس، البنية، التوقيع مطابق لنمط `SecurityAdminPlugin.kt` الموجود مسبقاً وناجح)، لكن لم يُجمَّع (compile) فعلياً بـ Gradle هنا.

**الخطوة التالية المطلوبة منك قبل الاعتماد على هذه النسخة لبيانات حقيقية:**
```bash
npm install
npm run typecheck
npm test
npm run android:setup
npm run apk:debug
```
أول رسالة خطأ من أي أمر فوق هي اللي لازم تُحل أولاً — شاركني ياها وبساعدك فيها.
