# دليل التشغيل والبناء بالعربية

## أ. تشغيل نسخة الويب للتجربة

1. ثبّت Node.js 22 أو إصدارًا متوافقًا.
2. افتح Terminal في جذر المشروع الذي يحتوي `package.json`.
3. نفّذ:

```bash
npm ci
npm test
npm run typecheck
npm run dev
```

افتح العنوان الذي يطبعه Vite. نسخة الويب للتجربة؛ وظائف Android الأصلية مثل BiometricPrompt أو AppLock فوق التطبيقات الأخرى لن تعمل داخل المتصفح.

## ب. بناء APK على Windows

1. ثبّت Android Studio، ومن SDK Manager حمّل Android SDK Platform وأدوات Build Tools وPlatform Tools المتوافقة مع Capacitor 7.
2. ثبّت JDK الذي يتوافق مع نسخة Android Gradle Plugin التي ينشئها Capacitor. تأكد أن Android Studio يستطيع تشغيل Gradle قبل متابعة التطبيق.
3. فك أرشيف المشروع بمجلد عادي وافتح PowerShell فيه.
4. نفّذ بالترتيب:

```powershell
npm ci
npm test
npm run typecheck
npm run apk:debug
```

`apk:debug` يبني نسخة SPA للموبايل، ويستدعي سكربت إعداد Capacitor، وينشئ/يحدّث مجلد `android`، ثم يشغّل المزامنة وGradle. المسار المتوقع:

`android/app/build/outputs/apk/debug/app-debug.apk`

إذا ظهر أول خطأ من npm أو TypeScript أو Gradle، توقّف واحتفظ برسالة الخطأ كاملة؛ لا تعتبر بناء APK ناجحًا بمجرد وجود مجلد `android`.

## ج. تثبيت APK على هاتف اختبار

1. لا تستخدم هاتفك الأساسي لتجربة Device Owner أو سياسات Kiosk.
2. فعّل Developer options وUSB debugging في هاتف الاختبار، ثم وصله بجهاز التطوير.
3. أسهل طريقة: افتح `android/` في Android Studio وشغّل التطبيق على الجهاز. أو نفّذ `adb install -r android/app/build/outputs/apk/debug/app-debug.apk` بعد نجاح البناء.
4. افتح التطبيق وانتظر استعادة الحالة قبل إدخال PIN.

## د. اختبار الرموز

- `0000`: دخول طبيعي.
- الحاسبة هي شاشة البداية. تعمل العمليات الحسابية عاديًا؛ للوصول إلى مساحة الحماية اضغط خيار المالك الظاهر ثم أدخل `0000` أو رمز المالك الذي ضبطته. لا يؤدي تعبير حسابي مخفي إلى مسح أو قفل.
- عند فتح الخزنة لأول مرة، أنشئ كلمة مرور مستقلة بطول 12 محرفًا على الأقل وأكدها. عند فتح الخزنة لاحقًا، أدخل كلمة المرور نفسها. كلمة المرور لا تُحفظ؛ إذا نسيتها فلن يمكن فك الخزنة.
- `5555`: قفل داخل التطبيق 30 يومًا. رمز المالك الرئيسي يتيح استرداد الوصول. لا تستخدمه في هاتفك الأساسي إذا كنت غير مستعد للبقاء في شاشة القفل داخل التطبيق.
- `7777`: مسح بيانات التطبيق فقط. جرّبه باستخدام ملفات وملاحظات تجريبية لا قيمة لها.
- أي رمز آخر: رفض؛ مهلة المحاولات محفوظة عبر إعادة فتح التطبيق وتتضاعف بعد كل دورة فشل حتى 24 ساعة. بعد انتهاء المهلة يمكن المحاولة مجددًا؛ لا يحدث مسح تلقائي للهاتف.

في بيئة التطوير فقط، يمكن تقصير القفل باستخدام `?lockSeconds=60` في عنوان Vite لتجربة الانتهاء خلال دقيقة. هذا الاختصار يتجاهل في بناء الإنتاج.

## هـ. تفعيل الصلاحيات الأصلية

- **Device Admin:** داخل الإعدادات، اضغط التفعيل ووافق على حوار Android. يستعمله هذا المشروع لطلب `lockNow()` فقط. يمكن إلغاء تفعيله من إعدادات أمان النظام.
- **BiometricPrompt:** سجّل بصمة/وسيلة حيوية في Android أولاً، ثم فعّل الدخول الحيوي من التطبيق. هذه خطوة واحدة للدخول العادي فقط.
- **قفل تطبيقات أخرى:** من داخل التطبيق اعمل Scan للتطبيقات المثبّتة، اختر الحزم، ثم اذهب إلى إعدادات Android > Accessibility > Installed/Downloaded apps وفعّل خدمة Duress Security. وصف الخدمة ظاهر في Android؛ وهي تقرأ اسم الحزمة الأمامية فقط. عطّلها من نفس المكان عند الاختبار.
- **Overlay/Usage/Notifications:** كل بند يفتح صفحة الإعدادات الحقيقية المتاحة؛ رجّع للتطبيق لكي يقرأ الحالة من النظام. التشغيل التلقائي ليس إذن Android موحدًا، لذلك لا يظهر كمفعّل كذبًا.
- **Device Owner/Kiosk/منع الإزالة:** لا تحاول التفعيل على الهاتف العادي؛ اتبع ملف `DEVICE_OWNER_KIOSK_AR.md` على هاتف ثانٍ مخصص فقط.

## و. ماذا لا يفعله التطبيق؟

لا يستبدل شاشة قفل Android، ولا يقرأ رمزها، ولا يعطّل الإقلاع، ولا يمسح الهاتف كاملًا، ولا يمكنه معرفة أي إصبع سجل الدخول. Kiosk وضع جهاز مخصص قابل للاسترداد، وليس وسيلة لإبطال مالك الجهاز.

## ز. نتائج التحقق الحالية

- `node --test 'scripts/**/*.test.mjs'`: **206/206 ناجحة**.
- `node --experimental-strip-types --test src/lib/security-service.test.ts src/lib/vault-crypto.test.ts src/lib/native-bridge.test.ts`: **27/27 ناجحة**.
- `npm test` كاملًا: اختبارات السكربتات نجحت، لكن نجحت اختبارات TypeScript المتاحة 33/35؛ تعذّر تحميل مجموعتين لاستخدامهما `@tanstack/react-start` و`jose` لأن npm فشل بتنزيل الاعتماديات (DNS `EAI_AGAIN`).
- `npm run typecheck`: تعذر بسبب غياب `@types/node` و`vite/client` بعد فشل تثبيت الحزم.
- APK/Kotlin/Gradle: لم يُبنَ في هذه الجلسة لعدم توفر Android SDK وGradle.

نسخة الويب تخزّن الخزنة مشفرة، لكن إعدادات التطبيق ورموزه ما زالت ضمن مخزن Zustand للمتصفح. لا تستخدم نسخة الويب لبيانات حقيقية شديدة الحساسية قبل تشفير كامل حالة التطبيق. Android لديه طبقة تخزين إضافية بمفتاح Android Keystore، لكنها ما زالت تحتاج اختبار بناء على جهاز فعلي.
