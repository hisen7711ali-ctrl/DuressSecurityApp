# الملف التعريفي التفصيلي — Duress Security App

## 1. الفكرة

تطبيق مشروع تخرج لتجربة حماية ذات طبقات داخل التطبيق: رموز متعددة، خزنة/ملفات محلية تجريبية، قفل لمدة محددة، واجهة آلة حاسبة، ومكوّن Android أصلي لبعض وظائف النظام. لا يدّعي أنه بديل لقفل Android، ولا يقرأ الرمز النظامي أو يحاول تجاوزه.

## 2. التقنية ونقطة التشغيل

- الواجهة: React + TypeScript.
- إطار التطبيق: TanStack Start مع Vite.
- إدارة الحالة: Zustand persist.
- تطبيق Android: Capacitor 7 + Kotlin.
- مدخل الواجهة: `src/routes/index.tsx` ثم `src/components/app-shell.tsx`.
- منطق الرموز: `src/lib/security-service.ts`.
- التخزين: `src/lib/app-storage.ts`.
- جسر Android: `src/lib/native-bridge.ts` و`android-native/plugin/src/main/java/com/duresssecurity/admin/SecurityAdminPlugin.kt`.

## 3. مخطط معماري

```text
src/routes/index.tsx
  └─ src/components/app-shell.tsx
      ├─ LockGate / PinKeypad
      ├─ ExtendedLockScreen
      ├─ FakeCalculator
      ├─ HomeScreen / AppsScreen / FilesScreen / SettingsScreen
      └─ PinsPanel

src/lib/store.ts ─────────── Zustand وإجراءات الشاشة
  ├─ security-service.ts ─── تصنيف PIN، القفل، المسح المحدود
  ├─ app-storage.ts ──────── متصفح للتجربة أو تخزين Android مشفر
  └─ native-bridge.ts ────── واجهة Capacitor
       └─ SecurityAdminPlugin.kt
           ├─ Device Admin / lockNow
           ├─ BiometricPrompt
           ├─ SecureStorage.kt (AES-GCM + Android Keystore)
           ├─ AppLockAccessibilityService.kt
           ├─ BootCompletedReceiver.kt
           └─ Device Owner/Kiosk methods
```

## 4. الرموز

| الرمز الافتراضي | سلوك التطبيق | الحد الفاصل |
|---|---|---|
| `0000` | الدخول العادي | لا يفتح قفل Android نفسه |
| `4444` | آلة حاسبة تعمل محليًا داخل التطبيق | لا يخفي اسم/أيقونة التطبيق في مشغل Android |
| `5555` | قفل واجهة التطبيق لمدة 30 يومًا | لا يمنع إقلاع الهاتف أو قبول PIN النظام؛ مالك التطبيق يستطيع الاسترداد بالرمز الرئيسي |
| `7777` | مسح سجلات وبيانات النموذج التي يملكها التطبيق | لا ينفذ factory reset أو يمسح تطبيقات أخرى |
| غير ذلك | رفض الإدخال واحتساب محاولات خاطئة | حظر متصاعد على مستوى التطبيق، من 20 ثانية افتراضيًا إلى 24 ساعة كحد أقصى؛ لا يؤثر على Keyguard النظامية |

الأرقام العربية والهندية والفارسية تُحوّل إلى أرقام ASCII قبل المقارنة. يمكن تغيير الرموز من واجهة الإعدادات مع رفض القيم المكررة.

## 5. التخزين والحماية

نسخة Android توجّه بيانات Zustand وسجل القفل المنفصل إلى جسر Kotlin. `SecureStorage.kt` يشفر كل قيمة بـ AES-GCM، بينما يبقى مفتاح AES داخل Android Keystore. عند فشل فك التشفير لا يتعامل التطبيق مع السجل التالف على أنه سجل فارغ ولا يهاجر فوقه بيانات نصية قديمة. مسح `7777` يفرغ مساحة التخزين المشفرة ذات البادئة الخاصة بالتطبيق وبيانات الويب الخاصة به ثم يعيد القيم التجريبية الافتراضية.

نسخة الويب تحفظ الخزنة في سجل منفصل مشفر باستخدام AES-256-GCM ومفتاح مشتق بـ PBKDF2-SHA-256 (310,000 تكرار) من كلمة مرور لا تقل عن 12 محرفًا، بملح عشوائي وIV جديد لكل حفظ. بعد ترحيل الخزنة، لا يعود حقل الملفات ضمن حالة Zustand المحفوظة. لكن PIN والإعدادات العامة ما زالت ضمن `localStorage` في نسخة الويب؛ فلا ينبغي استخدامه كحاجز أمني كامل قبل إضافة تشفير شامل لحالة الويب. ملفات الخزنة ظاهرة في ذاكرة التطبيق وهي مفتوحة.

نسخة APK تشفر حالة التطبيق العامة عبر AES-GCM ومفتاح Android Keystore، وتضيف طبقة تشفير منفصلة للخزنة. تعطيل Android auto-backup يقلل خطر استعادة ciphertext من دون مفتاح الجهاز. لا يضمن ذلك الحماية من جهاز مروّت أو بيئة debug مخترقة أو تحليل أثناء فتح الخزنة.

قفل الثلاثين يومًا يعتمد أيضًا على ساعة النظام المحلية؛ ليس مقاومًا لكل طرق تغيير الساعة أو العبث بالنظام، لذلك لا يجوز وصفه بقفل زمني لا يمكن تجاوزه.

## 6. قفل التطبيقات الأخرى

في APK يمكن للمستخدم تفعيل `AppLockAccessibilityService` يدويًا من إعدادات Android. الخدمة تستقبل تغيّرات حالة النافذة وتقرأ اسم الحزمة فقط؛ `canRetrieveWindowContent=false` و`canRequestFilterKeyEvents=false`. عند انتقال المستخدم إلى حزمة اختارها داخل التطبيق، تعرض طبقة وصول كاملة تطلب الرمز الرئيسي، وتوفر مسار استرداد بالرجوع إلى التطبيق نفسه.

هذه الخدمة تتطلب موافقة صريحة، وقد تتصرف بعض الشركات المصنّعة بصورة مختلفة. ليست ضمانًا لمنع كل طرق تجاوز النظام. المستخدم يستطيع تعطيل خدمة إمكانية الوصول من إعدادات Android. على متصفح/PWA لا يمكنها قفل تطبيقات الهاتف الأخرى.

## 7. المسؤولية وKiosk

`DeviceAdminReceiver` يتيح حوار تفعيل مسؤول الجهاز وتستخدم هذه الصلاحية هنا لطلب `lockNow()` فقط. أما منع إزالة التطبيق عبر `setUninstallBlocked` وLock Task Mode فيتطلبان `Device Owner`، لذلك لن يعمل الزر على هاتف عادي، بل يعرض توضيحًا. يتم تجهيز Device Owner عادةً على جهاز اختبار مخصص بعد تهيئته بالطريقة المطلوبة. خطوات الإعداد والخروج موجودة في `docs/DEVICE_OWNER_KIOSK_AR.md`.

## 8. قفل النظام والبيومترية

`MainActivity.kt` يضع `setShowWhenLocked` و`setTurnScreenOn` لتحسين ظهور واجهة التطبيق في الظروف التي يسمح بها النظام، ويستخدم `FLAG_SECURE` لمنع لقطات الشاشة. هذه الإعدادات لا تستبدل Android Keyguard ولا تتجاوز رمز النظام. `lockNow()` يطفئ/يقفل الشاشة وفق سياسة الجهاز لكنه لا يغيّر رمز قفل Android.

`BiometricPrompt` يسمح بمصادقة حيوية واحدة للدخول الطبيعي. لا يوفر معرفًا للإصبع المحدد؛ لذلك لا يمكن إجراء ربط آمن من نوع «إصبع للمسح وإصبع للقفل». الإجراءات الحساسة تتطلب PIN صريحًا.

## 9. إعادة التشغيل

بعد اكتمال الإقلاع، يحاول `BootCompletedReceiver` قراءة سجل القفل المشفر. إن كان القفل لا يزال ساريًا، يرسل إشعارًا مرئيًا يمكن النقر عليه لفتح التطبيق. لا يحاول بدء واجهة مخفية من الخلفية ولا يضمن ظهورها فوق قفل النظام. عند بدء التطبيق، تُستعاد حالة القفل وتُفحص صلاحية تاريخ الانتهاء.

## 10. الحاسبة والرموز

الحاسبة هي شاشة البداية في الحالة العادية. عملياتها الحسابية تعمل محليًا دون `eval` أو `new Function`. للوصول إلى مساحة الحماية، استخدم خيار المالك الصريح ثم أدخل رمز المالك؛ الضغط على `%` أو `=` أو نتيجة معينة لا ينفّذ أمرًا مخفيًا. المحاولات الخاطئة تفعّل مهلة متصاعدة تحفظ عبر إعادة فتح التطبيق حتى 24 ساعة، لا إعادة ضبط مصنع.

## 11. بناء APK والتحقق

```bash
npm ci
npm test
npm run typecheck
npm run apk:debug
```

المسار المتوقع: `android/app/build/outputs/apk/debug/app-debug.apk`. لا يوجد APK مرفق من هذه الجولة لأن Android SDK/Gradle لم يكونا متاحين. اجتازت اختبارات سكربتات المشروع 206/206، واختبارات الحماية/التخزين/الجسر المستقلة 27/27. فشل اكتمال `npm test` بسبب حزم لم تُنزّل مع خطأ DNS، وفشل TypeScript لفقدان تعريفات Node/Vite؛ تجميع Kotlin وGradle واختبارهما ما زالا مطلوبين على جهاز التطوير.
