# Duress Security App — نسخة مشروع التخرج

المشروع الفعلي هو **React + TypeScript** باستخدام TanStack Start/Vite وZustand، مع جسر Android أصلي اختياري عبر Capacitor/Kotlin. ليس مشروع .NET MAUI. هذه نسخة تعليمية قابلة للتجربة؛ لم تخضع لمراجعة أمنية مستقلة.

## ما تغيّر في هذه النسخة

- تبدأ الواجهة العادية بآلة حاسبة تعمل محليًا. يوجد خيار واضح لفتح مساحة الحماية، ثم يطلب التطبيق رمز المالك. لا يفعّل إدخال تعبير حسابي مخفي عمليات مسح أو قفل؛ الحسابات العادية لا تنفّذ أوامر جانبية.
- أضيفت خزنة مستقلة بتشفير AES-256-GCM، ومفتاح مشتق من كلمة مرور يختارها المستخدم عبر PBKDF2-SHA-256 بعدد 310,000 تكرار وملح عشوائي 128-bit. كلمة مرور الخزنة يجب أن تكون بطول 12 محرفًا على الأقل. لا يُحفظ مفتاح فك التشفير في التخزين، ويُقفل في الذاكرة عند مغادرة تبويب الخزنة.
- في APK، تبقى حالة التطبيق العامة أيضًا داخل تخزين AES-GCM بمفتاح محفوظ في Android Keystore. الخزنة لها طبقة تشفير إضافية. إذا فشل فك التشفير أو اختفى السجل المشفّر، لا يُستبدل تلقائيًا بخزنة فارغة.
- بعد نجاح ترحيل الخزنة إلى التشفير، لا يعود حقل الملفات محفوظًا داخل JSON العام. الملفات الجديدة تُكتب إلى سجل الخزنة المشفّر فقط.
- عداد المحاولات ووقت الحظر محفوظان ضمن حالة التطبيق؛ تتضاعف مهلة الحظر مع كل دورة تخمين فاشلة وتصل إلى 24 ساعة كحد أقصى، وتُصفّر عند نجاح رمز المالك. إعادة فتح التطبيق لا تلغي المهلة.
- مسح `7777` يبدأ فورًا إزالة بيانات التطبيق التي يملكها فقط، بما فيها الخزنة المشفّرة. تعرض الواجهة بوضوح أن بيانات الهاتف وبقية التطبيقات لا تتأثر، وتعرض فشلًا إذا تعذّر تأكيد الحذف.

## الرموز الافتراضية

| الرمز | الوظيفة |
|---|---|
| `0000` | الدخول العادي إلى مساحة الحماية؛ اضغط خيار المالك في شاشة الحاسبة أولًا |
| `4444` | العودة إلى واجهة الحاسبة داخل التطبيق |
| `5555` | قفل مساحة التطبيق لمدة 30 يومًا، مع حفظ وقت الانتهاء واستعادة الحالة |
| `7777` | إعادة تهيئة بيانات التطبيق والخزنة فقط، وليس الهاتف |
| غير ذلك | رفض الإدخال مع مهلة بعد تكرار المحاولات |

يمكن تخصيص الرموز من الإعدادات. تُطبّع الأرقام العربية والفارسية قبل المقارنة. إبقاء رمز `0000` الافتراضي مخصص للتجربة فقط؛ غيّره قبل أي عرض عام.

## بنية الملفات

- `src/components/app-shell.tsx`: اختيار شاشة البداية والقفل والواجهة الرئيسية.
- `src/components/fake-calculator.tsx`: آلة حاسبة البداية، لا تستخدم `eval` أو `new Function` ولا تشغّل أوامر خفية من النتيجة.
- `src/components/files-screen.tsx`: إنشاء كلمة مرور الخزنة، فتحها، وعرض ملفاتها وتعديلها.
- `src/lib/vault-crypto.ts`: تشفير/فك تشفير الخزنة للويب وCapacitor WebView عبر Web Crypto.
- `src/lib/store.ts`: رموز التطبيق، القفل، مهلة المحاولات، وحالة ترحيل الخزنة.
- `src/lib/app-storage.ts`: تخزين المتصفح أو التوجيه إلى التخزين الأصلي المشفّر في Android.
- `android-native/plugin/src/main/java/com/duresssecurity/admin/SecureStorage.kt`: AES-GCM مع Android Keystore لحالة التطبيق في APK.
- `android-native/plugin/.../SecurityAdminPlugin.kt`: الوظائف الرسمية مثل BiometricPrompt وDevice Admin وLock Task لجهاز Device Owner.
- `scripts/android-setup.mjs` و`scripts/build-apk.mjs`: إعداد مشروع Capacitor/Android وبناء debug APK.

## حدود الحماية المهمة

- تشفير الخزنة في المتصفح يعتمد على كلمة مرور قوية، وHTTPS أو سياق آمن يدعم Web Crypto. الملفات مكشوفة في ذاكرة التطبيق بينما الخزنة مفتوحة. بقية حالة واجهة الويب مثل PIN والإعدادات لا تزال محفوظة في مخزن Zustand للمتصفح؛ لذلك نسخة الويب ليست حاجزًا أمنيًا مماثلًا لتخزين Android Keystore، ولا ينبغي وضع أسرار حقيقية فيها قبل إكمال تشفير حالة الويب بالكامل ومراجعتها.
- لا يستبدل التطبيق شاشة Android Keyguard، ولا يقرأ PIN النظام ولا يعترض محاولات فتحه. رمز `5555` لا يمنع إقلاع الهاتف ولا يتجاوز رمز النظام.
- لا تُنفّذ إعادة ضبط مصنع من `7777` أو تلقائيًا بعد محاولات خاطئة. الحماية هنا تستخدم حظر تخمين متصاعد محفوظ حتى 24 ساعة بدل مسح جهاز غير قابل للتراجع.
- لا نخفي إشعارات نظام الحماية أو نمنع المالك من مسار الاسترداد. سياسات Kiosk ومنع الإزالة لا تعمل إلا على جهاز اختبار جرى إعداده صراحةً كـ Device Owner، وتحتاج طريق خروج موثقًا.
- `BiometricPrompt` لا يكشف أي إصبع بعينه؛ لا يمكن ربط كل إصبع بإجراء مختلف باستخدام الواجهة القياسية.

## الاختبارات والبناء

الأوامر المعتادة:

```bash
npm ci
npm test
npm run typecheck
npm run apk:debug
```

في هذه البيئة، نجحت اختبارات سكربتات المشروع **206/206**، ونجحت اختبارات الحماية/التخزين/الجسر المستقلة **27/27**. كما فحصت اختبارات جديدة سلوك الشاشة الأولى، وتشفير الخزنة، وبقاء مهلة المحاولات.

تعذّر إكمال `npm test` بالكامل لأن تنزيل الاعتماديات توقف بخطأ DNS (`EAI_AGAIN registry.npmjs.org`): نجحت اختبارات السكربتات 206/206، ونجحت 33 من اختبارات TypeScript بينما تعذّر تحميل اختبارين لغياب `@tanstack/react-start` و`jose`. وفشل `npm run typecheck` لأن تعريفات `node` و`vite/client` غير موجودة. لم يتوفر Android SDK/Gradle للبناء؛ **لم يُنتج APK ولم يُجمع Kotlin في هذه الجلسة**.

لخطوات تشغيل الويب وبناء APK وإعداد جهاز اختبار، راجع `docs/README_AR.md` و`docs/DEVICE_OWNER_KIOSK_AR.md`. تعليمات دفع النسخة للمستودع الخاص موجودة في `GITHUB_PRIVATE_PUSH_AR.md`.
