# الآلة الحاسبة — Duress Security App

تطبيق Android أمني محلي بواجهة **آلة حاسبة** كواجهة أولى، مع بوابة حماية PIN، App Lock، Vault مشفّر، Kiosk/Device Owner وتكاملات Android الأصلية. الاسم الظاهر للتطبيق: **الآلة الحاسبة**، والـpackage هو `com.duresssecurity.app`.

> **الحالة:** المشروع قيد التطوير والتحقق. نجاح GitHub Actions وبناء APK لا يعني أن كل قيود Android الخاصة بالجهاز المُدار متاحة على كل هاتف؛ Device Owner يحتاج provisioning رسمي.

## أهم الوظائف الحالية

- آلة حاسبة حقيقية تعمل محليًا بدون `eval`.
- رمز فتح حاسبة قابل للتغيير، 8 أرقام، مع الحفاظ على الأصفار المتكررة مثل `00000000`.
- `0000` دخول فوري عندما يكون Master PIN مضبوطًا عليه.
- `4444` مسار Duress/الحاسبة الوهمية من سياق القفل، بدون مسح بيانات.
- `5555` وضع Extended Lock وصيانة لمدة 30 يومًا، مع محاولة قفل Android عبر `DevicePolicyManager.lockNow()` عندما تكون الشروط متاحة.
- `7777` مسار طوارئ لبيانات التطبيق التي يملكها التطبيق فقط؛ لا يستخدمه التطبيق لعمل Factory Reset ولا لمسح تطبيقات أخرى من لوحة القفل.
- App Lock منفصل لكل تطبيق محمي، مع اسم وأيقونة وخلفية مستقلة.
- خلفية مستقلة للقفل الرئيسي وApp Lock، مع preset/gallery وzoom/pan وحفظ التحويلات.
- BiometricPrompt للتحقق البيومتري بدون محاولة معرفة أي إصبع استُخدم.
- سجل محاولات فاشلة مشفّر ومقاوم لإعادة التشغيل، مع حدود محاولات ومهلة انتظار.
- Android Keystore وSecure Storage وAES-GCM.
- Vault يستخدم Argon2id v1.3 للبيانات الجديدة، مع قراءة/ترحيل صيغ PBKDF2 القديمة عند الحاجة.
- حماية التقاط الشاشة عبر `FLAG_SECURE` عند الدخول إلى الأسطح الحساسة.
- R8/ProGuard للـrelease مع قواعد keep ضيقة للمكونات الأصلية المطلوبة.
- Device Admin وDevice Owner/Kiosk عند provisioning الصحيح، مع عدم الادعاء أن Device Admin وحده يجعل التطبيق Device Owner.
- Accessibility App Lock ضمن القيود التي يفرضها Android.

## الدخول المخفي والحاسبة

تظهر الحاسبة كواجهة أولى عادية. رمز فتح بوابة الحماية الافتراضي التاريخي هو `20272006`، ويمكن تغييره من **الإعدادات ← إدارة أرقام PIN ← رمز فتح الحاسبة**.

- الرمز الجديد يجب أن يكون 8 أرقام.
- الأصفار في بداية الرمز أو داخله لا تُحذف.
- الرمز الجديد لا يجوز أن يطابق رموز الحماية الأربعة.
- بعد تغيير الرمز يصبح القديم غير صالح.
- الضغط على `=` بعد الرمز الصحيح يفتح بوابة الحماية مرة واحدة.

## PIN والحماية

| الرمز الافتراضي | الوظيفة |
|---|---|
| `0000` | Master PIN — الدخول العادي |
| `4444` | Duress / فتح واجهة الحاسبة الوهمية من سياق القفل |
| `5555` | Extended Lock / وضع الصيانة والقفل الممتد |
| `7777` | مسار الطوارئ لبيانات التطبيق المملوكة له، وليس Factory Reset |

هذه القيم افتراضية للمشروع ويجب تغييرها قبل الاستخدام الفعلي.

### لماذا لا يعمل Factory Reset من Device Admin فقط؟

Android يفرّق بين Device Admin وDevice Owner. عملية إعادة ضبط الجهاز إلى حالة المصنع يمكن لـ`DevicePolicyManager.wipeData()` تنفيذها ضمن صلاحيات وسياسة الجهاز المناسبة، وهي عملية تدميرية للجهاز كله. لذلك لا تُعامل كأنها مجرد `wipeAppData()` داخل WebView. citeturn0search1turn0search2

إذا أُضيف **مسح الجهاز الكامل** مستقبلًا فسيكون في التصميم الآمن للمشروع:

1. متاحًا فقط عندما يثبت Android أن التطبيق هو **Device Owner**.
2. خيارًا صريحًا يفعّله المالك من إعدادات الحماية.
3. مربوطًا برمز مستقل لا يتعارض مع Master/Lock/Duress/Calculator.
4. أول إدخال يسلّح العملية فقط ويعرض حالة خطأ مقصودة؛ لا يبدأ المسح.
5. يجب إدخال الرمز نفسه مرة ثانية لتأكيد العملية.
6. عندها فقط يستدعي المسار الأصلي Android API، وليس حذف ملفات عشوائيًا من التخزين.

بهذا الشكل لا يمكن لضغطة واحدة عابرة أن تعمل Factory Reset، ولا يتم تحويل `7777` الخاص بالـApp Lock إلى مسح للجهاز.

## مسح بيانات تطبيق محمي

مسح بيانات تطبيق آخر ليس هو نفسه Factory Reset. Android يوفّر `DevicePolicyManager.clearApplicationUserData()` للـDevice Owner/Profile Owner لمسح **بيانات المستخدم الخاصة بحزمة تطبيق محددة**؛ ولا ينبغي اعتبار ذلك ضمانًا لمسح كل الملفات التي قد تكون خارج مساحة بيانات التطبيق، مثل بعض محتوى التخزين الخارجي. citeturn0search10

لذلك أي مسار لـ`7777` داخل App Lock يجب أن يكون:

- خاصًا بالتطبيق المستهدف فقط.
- مفعّلًا صراحة من المالك لكل package.
- مشروطًا بأن التطبيق هو Device Owner فعليًا.
- منفصلًا تمامًا عن `7777` في القفل الرئيسي للتطبيق نفسه.

## Android Native

المشروع يستخدم:

- `DevicePolicyManager.lockNow()` لقفل الشاشة عندما تكون سياسة Android متاحة.
- `DevicePolicyManager`/Device Owner لـKiosk والسياسات المُدارة.
- `BiometricPrompt`.
- Android Keystore.
- Secure Storage أصلي.
- Accessibility App Lock.
- Boot/restart handling ضمن حدود Android الحديثة.
- `FLAG_SECURE` لمنع التقاط الأسطح الحساسة.

الـAPK لا يعتمد على خادم خارجي لعرض الواجهة الأساسية، ولا يحتاج اتصال إنترنت أثناء التشغيل الطبيعي.

## CI والتحقق

GitHub Actions يتحقق من:

- npm tests.
- TypeScript.
- Authentication/safety invariants.
- Android/Gradle compilation.
- بناء APK.
- صلاحيات وManifest النهائي.
- وجود MainActivity وDevice Admin وBoot Receiver وAccessibility service.
- عدم وجود صلاحيات شبكة أو `QUERY_ALL_PACKAGES` غير المطلوبة.
- lint.

تم تحديث workflows إلى `actions/setup-node@v5` و`actions/setup-java@v5` وتثبيت runner على `ubuntu-24.04` لتجنب تحذيرات تقادم البيئة.
